三

消融：易经卦象到底有没有用？

这是最必须说清、也最反直觉的一节。结论：承重的是 L2 六爻手工目标特征（本质是符号规划的评分函数）， 不是"易经卦象"。去掉整个 L3 卦象层，成绩几乎不变（valid_seen 129→128，McNemar p = 1.0）； 冻结 L2 六爻，成绩直接崩塌。

架构合规

卦象确实参与

卦象每步对所有候选打分、是唯一胜者选择器——无造假，但因果贡献微弱。

诚实定性

脚手架，非承重

《易经》是"符号骨架 + 命名 schema"；性能来自 NL 解析 + train 先验 + veto/重试（经典符号规划）。

四

与书中 92.5% / 73.9% / 90% 的性质区别

核心区别不在数值高低，而在口径。书中三个高分是"给系统喂答案 / 让系统反复看测试集 / 缩小分母"换来的； 我们的数字在"不喂答案、不删难题、每局重置"下取得。

书中口径 · 加持

  • 92.5% (v6)：喂 PDDL 真值目标 + oracle 任务类型 + 硬编码 FSM；卦象根本不参与决策
  • 73.9% (v10)：同一评测集跑 5 轮累积经验，测试集跨轮泄漏
  • 90% (子集)：删掉 34 局难题后的子集分母

我们的口径 · 诚实

  • 决策路径对 info 真值完全隔离；won 传入即丢弃，无 oracle、无按局 FSM
  • 每局 fresh agent，无跨局学习、无经验累积
  • 分母是标准全集（unseen 134 / seen 140），无删题
五

诚实的文献定位

绝不宣称"纯符号超越 27B LLM"。 两条不能混的坐标轴：归纳轴上我们 ~80%，低于干净 SOTA（EmbodiSkill 93.28）， 高于 ReAct/ExpeL/BUTLER；开发集轴上 98.5% 的唯一公平对照是 Reflexion 97%（同为多次重试的 transductive）。 真正的独特卖点是 无 LLM · CPU · ~2ms/步 · 完全确定可复现——算力比所有 LLM 竞品低若干数量级。

六

必须披露的局限

CRITICAL
依赖 env won 的有界闭环重试。 放置未触发 won 即判解析错、回退换候选重试（硬上限 ≤10 retry / 50 步）。几个最难的胜局靠"枚举撞中"而非一次性语言理解——须披露为 bounded trial-and-error，不能宣传成 zero-shot。
CRITICAL
valid_unseen 事实上被当开发集。 98.5% 是"在 unseen 上调过后的拟合"；唯一 OOD 数是冻结 79.9% + 留出 81.3%。
HIGH
L3 卦象层对结果贡献 ≈ 0；承重的是 L2 六爻特征（linear 共享之），不能记功于易经。
HIGH
大量 ALFWorld 特定词典/启发式（~58 词典条目 + 十余条护栏），非 zero-shot、非通用；目标仅"接收类"粒度，基准判定宽松放过空间限定。
HIGH
"443 参数"表述会误导——这 443 个卦象核心数几乎惰性；诚实容量 = 443 + ~50 手调常数 + ~58 词典 + regex + train 先验。
七

给老师的三条提醒

避免重蹈书中数字虚高的覆辙——这三条按重要性排序。

1

"泛化"只留给 79.9% / 81.3%，绝不给 98.5%。

书中 v10 栽在"测试集反复跑泄漏"。只要对外把 98.5% 称作"泛化 / 超越 LLM"，审稿人 5 分钟即可从我们自己的日志验证出"照失败调过"。泛化 headline 只放 79.9% / 81.3%，98.5% 明标"开发集上限"。

2

不要把 98.5% 归功于"易经 / 卦象"——我们自己的消融已证否。

书中 v6 栽在"卦象不参与决策却宣称易经驱动"。我们的卦象确实参与打分（架构合规），但消融显示 L3 净贡献 +1/274 局。诚实讲法：把《易经》定位为"符号骨架 + 命名 schema"，主动报告"卦象层中性"这一负结果——反而是可引用的科学贡献。

3

主动披露三件事，别等复现者发现。

① valid 被当开发集；② 依赖 env won 的闭环枚举试错；③ L3 卦象几乎惰性。主动披露不削弱成果——40% → 诚实泛化 ~80% / 开发集上限 98.5% 是真实的重大提升——它只让成果从"漂亮但可疑"变成"经得起对抗性复现与审稿"。
