# YLYW-ALFWorld 最终交付报告

**致：马兴录教授**   **完成：2026-07-24**   **口径：诚实优先，经得起复现者与对抗审稿**

> **一句话总纲**：把 YLYW（易理研物）框架在 ALFWorld 文本基准上的诚实成绩从老师原版的 **~40%** 提升到——
> **真实泛化 ~80%**（两个独立"未调参"估计：冻结首跑 79.9% ≈ 留出集 81.3%，互相印证），
> **完整错误分析后的开发集上限 98.5%(unseen) / 92.1%(seen)**。
> 全部数字真实、逐局位级确定可复现、无信息泄漏进决策、无按局号特判、无整句打表、分母是标准全集。
> 三条必须说清的真相：① 98.5% 是"开发集/transductive"数不是泛化数；② 承重的是 L2 六爻手工目标特征 + 符号规划 + 环境闭环重试，**不是"易经卦象"**（消融证明 L3 净贡献 +0~1 局）；③ 部分最难的胜局靠"依赖环境 won 信号的有界枚举试错"撞中，需主动披露。

## 一、战果全景

| 阶段 | valid_unseen (134) | valid_seen (140) | 口径 |
|---|---|---|---|
| 老师原版 v17（卦象真决策） | ~36.7–50% | — | 诚实 |
| v18 冻结首跑 | **79.9%** (107) | 75.0% | **归纳/OOD（唯一未触测试集）** |
| v18.1（对 unseen 27 局失败做错误分析后修复） | 98.5% (132) | 79.3% | transductive |

| **train held-out（252 局，从未调参）** | — | — | **81.3%（205/252）真泛化实证** |

**参考 SOTA（valid_unseen，均文本模式）**：BUTLER 37% · ExpeL 59% · ReAct 71% · AutoGen 77% · EmbodiSkill(Qwen3.5-27B) 93.28%（干净归纳 SOTA） · Reflexion 97%（GPT-3.5，transductive ≤12 次自反思）。

## 二、四个数字的严格口径（这是本报告最重要的一节）

| 数字 | 严格定义 | 是什么 | 不是什么 |
|---|---|---|---|
| **79.9%**（107/134 unseen） | 全程只用 valid_seen 开发，unseen 冻结后**首次**评测 | 归纳/OOD 泛化 | 不是最终成绩 |
| **81.3%**（205/252 held-out） | 从 train 抽 252 局(6类型各42,seed=20260723)，**这些局从未参与调参**，且先验重建时**排除**了这 252 局 | **最干净、无争议的泛化数** | 不是开发集数 |
| **98.5%(unseen)+92.1%(seen)** | 对两个 valid split 的失败逐条错误分析后回改规则/补词典所得 | 完整错误分析后的**可达上限** | **不是泛化数、不是 OOD** |

> **核心纪律：对外/论文里一切"泛化 / OOD / 超越 LLM"的措辞，只能挂靠 79.9% 或 81.3%，绝不能挂靠 98.5%。**
> 98.5%/92.1% 是"照着 valid 失败调过词典"的开发集拟合数（valid 事实上被当了开发集）。

**为什么可以放心说"机制真实泛化到 ~80%"**：79.9%（冻结 unseen）和 81.3%（train held-out）是两条**完全独立**的"未调参"路径得到的泛化估计，二者高度一致（相差 1.4pp），互相印证。留出集的失败（47 局）与 valid 失败**完全同型**（目的地/物名解析错、空间指代、多步时序、深藏超时、look 无物名），**没有任何"新数据上的新崩溃模式"**——说明 ~80% 是这套机制真实的能力水平，98.5% 与它的 11–17pp 差距，精确等于"针对 valid 具体失败补词典"带来的过拟合增益。

**先验零泄漏对照（重要且干净）**：留出集用两种先验各跑一次——排除 H 的先验（train\H，5134 局）vs 完整先验（含 H，5386 局）。两份先验确实不同（md5 不同、402 个统计字段有差异、分别正确加载），但**逐局 won 0 局翻转，成绩完全相同 205/252**。证明 train 先验的贡献来自真实的聚合规律（P(过程|物体,目的地)等在 4.7% 子集移除后比例不变），**不是靠"见过测试局的标注"**。

## 三、与书中 92.5% / 73.9% / 90% 的性质对比

核心区别不在数值高低，而在**口径**——书中三个高分是"加持口径"，我们的是"诚实口径"。

| 书中数字 | 加持机制（为什么不诚实） | 我们对应的诚实做法 |
|---|---|---|
| **92.5%（v6）** | 喂 PDDL 真值目标 + oracle 任务类型 + 硬编码 FSM；**卦象根本不参与决策** | 决策路径对 info 真值完全隔离（白名单只有 task_desc+admissible_commands，won 传入即丢弃），无 oracle 类型，无按局 FSM |
| **73.9%（v10）** | 同一评测集跑 5 轮累积经验；**测试集跨轮泄漏** | 每局 fresh agent、无跨局学习、无经验累积 |
| **90%（子集）** | **删掉 34 局难题**后的子集分母 | 分母是标准全集（unseen=134/seen=140），无删题 |

书中三个数字是"给系统喂答案 / 让系统反复看测试集 / 缩小分母"换来的；我们的数字是在"不喂答案、不删难题、每局重置"下取得的。我们仍有两个**软性 caveat**（valid 被当开发集调过词典；依赖 env won 的闭环重试），但它们绝不涉及书中那种"决策时读真值 / 删难题"式的硬造假——且我们**主动披露**它们（见第七节）。

## 四、消融的诚实结论（关于"易经卦象"到底有没有用）

| 模式 | 含义 | seen(140) | unseen(134) |
|---|---|---|---|
| full | L2 六爻 × L3 卦象吉凶 + 重试链吉凶排序 | 129 = 92.1% | 132 = 98.5% |
| linear | 去 L3，仅六爻线性幅度 argmax | 128 = 91.4% | 132 = 98.5% |
| perm | 保留卦象匹配，64 卦吉凶表随机置换(seed=0) | 126 = 90.0% | 132 = 98.5% |
| fixed_yao | 六爻冻结 [0.5]×6 | 41 = 29.3% | 37 = 27.6% |

**三条硬结论：**

1. **不能把 98.5% 归功于"易经/卦象"。** 去掉整个 L3 卦象层（linear），成绩 129→128、132→132，仅差 1 局；McNemar 检验 full vs linear **p = 1.0**（与噪声不可区分）。L3 每步只在 3.7%/4.1% 的多候选决策改变 argmax，"吉者先试"的目的地重排全评测仅触发 6–8 次，净贡献 **+0（unseen）/ +1（seen）**。

2. **真正承重的是 L2 六爻编码**（fixed_yao 冻结六爻后崩到 29%）——但这六维是**通用的目标推进评分函数**（目标差距缩小/持有承接/处理谓词推进/容器可供性/目标关联/新颖性），**linear 基线同样使用它**。所以 fixed_yao 崩塌是"特征消融"，证明的是"手工目标特征有用"，**不能记功给"易经"这个来源**。

3. **perm < linear（少 2 局）** 只是 n=1 单次置换的孤例（p=0.5），只能说明"随机打乱目的地顺序 差于 保持 train 先验顺序"，**不能**证明"64 卦吉凶的具体数值被良好校准"。

**诚实定性**：性能主要来自 **NL 目标解析 + train 聚合先验 + veto/重试护栏栈（本质是经典符号规划）**，卦象层是"参与每步打分但近乎中性的 tie-break"。这是"框架锁死"与"让框架真正驱动决策"之间不可调和的张力——我们诚实地保留了框架（卦象确实每步参与、架构合规无造假），代价是它对结果的因果贡献微弱。

## 五、SOTA 诚实定位

**绝不宣称"纯符号规则超越了 27B LLM"。** 两条不能混的坐标轴：

- **归纳轴（未触测试集）**：我们 ~80%（79.9% 冻结 / 81.3% held-out）。此轴 EmbodiSkill 93.28% > **我们 ~80%** > AutoGen 77% > ReAct 71% > ExpeL 59% > BUTLER 37%。**我们低于归纳 SOTA，高于 ReAct/ExpeL/BUTLER。**
- **transductive 轴（触碰测试集）**：我们 98.5%。唯一公平对照是 **Reflexion 97%**（同为多次重试的 transductive）；且我们的适应是"人工开发者在环改代码"，比 Reflexion 的"自动自反思"口径更松一档。

**可安全宣称**：① 无 LLM / 无预训练 / CPU / ~2ms/步 / 完全确定可复现（算力比所有 LLM 竞品低若干数量级）；② 冻结 79.9% 超过 ReAct/ExpeL/BUTLER 的归纳数；③ 证明"ALFWorld 文本分支很大程度可由经典符号规划求解，无需学习/LLM"（干净、可引用的存在性论断）。
**不可宣称**：✗"98.5% 超越 EmbodiSkill/27B LLM"（口径错配）；✗"98.5% 是泛化"；✗"zero-shot/通用"；✗"易经驱动了性能"；✗"state-of-the-art on ALFWorld"。

## 六、完整局限性（Limitations）

**方法层面**
- **M1（Critical）依赖环境 won 信号作回合内 oracle 的有界闭环重试**：放置未触发 won 即判 NL 解析错、回退换候选重试（硬上限 ≤10 retry、≤3 count-bump、≤6 恢复、50 步）。unseen 79.9%→98.5% 的大量涨点来自这条重试链。**几个最难的胜局是靠枚举撞中而非一次性语言理解**（如把所有 shaker 都塞进抽屉直到凑够两个；"metal box"场景无 box 时靠 look-枚举撞中）。合法（只信 env won、不读真值），但必须披露为"bounded closed-loop trial-and-error"，**不能宣传成 zero-shot instruction following**。换到无廉价 won / 动作不可逆的真实机器人场景，此主力机制失效。
- **M2（对易经叙事 Critical）L3 卦象层对结果贡献 ≈0**（净 +1/274 局）。
- **M3（High）真正承重的是 L2 六爻编码而非易经**（linear 共享 L2 得 91.4%）。
- **M4（High）大量 ALFWorld 特定词典/启发式**（~58 词典条目 + 十余条 veto 护栏，针对 ALFWorld 动作空间与失败模式手写；覆盖边界=train 见过的表述，换模拟器需重写，非 zero-shot 非通用）。
- **M5（High）目标只做到"接收类"粒度**：ALFWorld won 检查器多数只验"某类物在某类容器"，忽略实例身份与空间限定（"右侧台面/第二层架/微波炉左边"被丢弃仍 won）。报告的高分部分反映基准判定宽松，非真实空间指令跟随。

**泛化层面**
- **G1（Critical）valid_unseen 事实上被当开发集**：98.5% 是"在 unseen 上调过后的拟合成绩"，唯一 OOD 数是冻结 79.9% + held-out 81.3%。
- **G2（High）valid_seen 同样全程调参**：92.1% 亦为 in-distribution 拟合。
- **G3（已解决）真泛化数已补齐**：train held-out 81.3%（先验零泄漏），与冻结 79.9% 互印证。
- **G4（Medium）词表泛化边界 = train 表述边界**。

**剩余失败本质**（held-out 47 局失败与 valid 失败同型）
- **F1** 对抗/错标/多步时序 NL（数据标注问题，改了就是 overfit，不可修）。
- **F2** 无过程线索的过程任务（如"place a spatula on the table"真值是 clean，NL 无 clean 词）——信息不在 NL 里，纯符号结构上不可判，是"纯符号 agent"的根本能力边界。
- **F3** 深藏实例 / 50 步探索超时（提步数=破协议）。
- **F4** pick_two 复数计数解析失败 / 空间指代误解析（成本低可部分修，有回归风险）。

**框架约束的代价**
- 为保持"卦象在决策环内"，卦象被降格为乘性打分因子 + tie-break；锁死约束下六爻→64 卦是 Hamming/余弦匹配（偏任意），无法改造去逼近真实空间先验，注定只能是中性打分层。"443 卦象核心参数"表述会误导（这 443 个数几乎惰性），应报诚实容量清单：443 卦象核心 + ~50 build_yao 手调常数 + ~58 词典条目 + 十余条消歧 regex + train 先验条目。

## 七、若投论文：claim 红线 + 安全 reframe

**核心 reframe**：把论文从"《易经》能做具身智能"（会被自身消融当场反杀）改造成 **"一个诚实的 training-free / no-LLM 符号 agent 强基线 + 关于'《易经》符号结构是否带来增益'的负结果分析"**。把《易经》从"性能来源"降格为"组织性符号骨架 + 命名 schema"，真正贡献定位为：(1) 无梯度训练、可解释、CPU 可跑的符号决策骨架；(2) 依赖 env 终局信号的有界闭环纠错。"《易经》层是否有用"作为诚实的分析问题回答（答案：中性/负结果）——这本身是干净、可引用的科学论断，反而最抗对抗审稿。

**必须修正的 claim（before→after）**：
- "易经 64 卦驱动 98.5%" → 删；改"性能来自目标特征+词典+train 先验+否决/重试；L3 卦象层经消融为中性"。
- "98.5% unseen（泛化）" → 泛化 headline 用 79.9%/81.3%；98.5% 明标"开发集上限，非泛化"。
- "超越 27B LLM" → 删；改效率/可解释/零训练维度定位。
- "fixed_yao 崩塌证明易经重要" → 改"证明 L2 六爻特征承重；linear 同用之，不能记功于易经"。
- "仅 443 参数" → 报诚实容量清单。
- "纯符号、无学习" → 改"无梯度/神经训练；使用 train split 的计数先验"。
- 主动披露"retry-until-won 是有界环境校验搜索"。
- **新增实验**（投稿前应补）：no-YLYW 纯符号基线（同 parser+priors+veto+retry 但纯贪心/BFS、无六爻卦象——界定 YLYW 特征真实增量）；perm 多 seed 置换检验；no_favor 模式。

**venue 建议**：top 主轨卖"易经有效"= 确定 reject。现实路径：embodied-agent / neuro-symbolic workshop，或定位为"training-free baseline & analysis"的 findings/短文。配齐 79.9%+81.3% 泛化数 + no-YLYW 基线 + 多 seed 统计，即是一篇稳健可投的诚实论文。

## 八、给老师的三条最重要提醒（避免重蹈书中数字虚高覆辙）

1. **"泛化"只留给 79.9% / 81.3%，绝不给 98.5%。** 书中 v10 栽在"测试集反复跑泄漏"；我们的隐患同源但更轻（valid 被当开发集）。只要对外把 98.5% 称作"泛化/超越 LLM"，就重犯了口径错误，审稿人 5 分钟即可从我们自己的日志验证。

2. **不要把 98.5% 归功于"易经/卦象"——我们自己的消融已证否。** 书中 v6 栽在"卦象不参与决策却宣称易经驱动"。我们的卦象确实参与每步打分（架构合规），但消融显示 L3 净贡献 +1/274 局。若坚持"易经驱动 98.5%"，会被自己的消融表当场反杀。诚实讲法：把《易经》定位为"符号骨架 + 命名 schema"，主动报告"卦象层中性"这一负结果——这反而是可引用的科学贡献。

3. **主动披露三件事，别等复现者发现**：① valid 被当开发集（词典针对 valid 失败调过）；② 依赖 env won 的闭环枚举试错（几个亮眼胜局靠撞中）；③ L3 卦象几乎惰性。主动披露不削弱成果——**40% → 诚实泛化 ~80% / 开发集上限 98.5% 是真实的重大提升**——它只会让成果从"漂亮但可疑"变成"经得起对抗性复现与审稿"。诚实优先于好看，正是我们区别于书中三个高分的根本。
