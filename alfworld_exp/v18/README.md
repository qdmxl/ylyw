# YLYW 符号规划 Agent 在 ALFWorld 上的未调参泛化评测

> 本文件报告 YLYW（易理研物）三层符号框架在 ALFWorld 文本环境上的评测结果，重点是**未调参口径下的泛化性能**，
> 以及使成绩从约 40% 提升至约 80% 的具体方法。所有数字均在诚实评测协议下取得，逐局位级确定可复现。

---

## 摘要

YLYW 是一个纯符号、无大语言模型、无梯度训练、可在 CPU 上以约 2 ms/步运行的具身决策框架（三层结构：L1 八卦原型 → L2 六爻六维状态编码 → L3 六十四卦策略模板）。本工作在不改动其核心引擎的前提下，重建了外围的语言解析、世界建模、探索与重试控制，将系统在诚实口径下的成绩从原实现的约 40% 提升至如下水平。

在**未参与任何调参**的评测口径下：

| 评测集 | 成功率 | 说明 |
|---|---|---|
| valid_unseen 冻结首跑 | **79.9%**（107 / 134） | 开发全程仅使用 valid_seen，unseen 冻结后首次评测 |
| train 留出集 | **81.3%**（205 / 252） | 从 train 抽取、从未参与调参，且先验重建时排除该子集 |

两个相互独立的未调参估计高度一致（相差 1.4 个百分点），共同表明该方法的真实泛化水平约为 **80%**。

---

## 1. 评测协议

### 1.1 环境与数据

- 基准：ALFWorld（文本模式，基于 TextWorld / PDDL 引擎，不使用视觉仿真）。
- 评测集：valid_unseen（134 局，房间布局与物体配置在训练集中未出现）、valid_seen（140 局）、train（8810 局，用于统计先验与本报告的留出集）。
- 单局步数上限：50 步。
- 运行环境：CPU，无 GPU、无外部 API 调用。

### 1.2 诚实口径的定义

为保证结果可复现且无信息泄漏，全部评测遵循以下约束：

1. **胜负仅由环境判定**：成功与否只取环境返回的 `won` 信号（TextWorld 的 PDDL 目标检查）。Agent 不读取该信号用于决策，不存在任何"自报完成"的通路。
2. **信息白名单**：Agent 每步仅可见任务描述 `task_desc`、当前观察 `observation`、可执行动作集 `admissible_commands`。任务类型、PDDL 参数等真值仅供评测端事后统计，决策路径完全隔离。
3. **每局独立**：每局使用全新的 Agent 状态，无跨局经验累积、无跨局学习。
4. **分母完整**：报告的分母为标准评测集全集（unseen 134 / seen 140），未删除任何难题子集。
5. **无按局特判**：不存在按局号硬编码或按任务描述整句到答案的映射；所使用的词典均为通用的"词/短语 → 类别"映射。

---

## 2. 口径说明：归纳 vs. 转导

ALFWorld 上的成功率必须区分两种口径，二者不可混用：

- **归纳（inductive / 未调参）**：评测集在开发过程中从未被观察、从未针对其失败模式做过调整。此口径反映真实泛化能力。
- **转导（transductive / 开发集）**：评测集的失败被逐条分析、并据此回改规则或补充词典。此口径反映的是"完整错误分析后的可达上限"，不代表泛化。

**本报告的主结果（第 4 节）为归纳口径**，其性能来自第 3 节所述的通用性方法改动。转导口径的结果（第 5 节）单独列出并明确标注，用于量化"针对性调优"带来的增益上界，不作为泛化主张的依据。

---

## 3. 方法：从约 40% 到约 80% 的关键改动

YLYW 原实现（记为 v17）在相同诚实口径下的成绩约为 37%–50%（下称约 40%）。其失败几乎全部集中于外围的世界建模、探索与控制逻辑，而非卦象核心。本工作在**不改动核心引擎**（`hanzi_engine.py`、`ylyw_action_primitives.py`）的前提下重建外围，使冻结泛化提升至 79.9%。以下五项改动**均为通用性修复**——针对的是系统性的架构缺陷与失败模式，而非任何评测集的具体失败——因此其收益属于归纳泛化。

### 3.1 修复决策—反馈时序缺陷

原实现中，同一次环境交互被状态更新逻辑重复记账，且反馈逻辑在动作执行**之前**消费了动作前的观察，导致系统频繁误判"某位置已搜索且无目标"，进而在若干位置之间无限往返直至步数耗尽。新实现采用严格的两段式接口——决策 `act` 与转移观测 `observe_transition` 分离，每次环境转移仅被消费一次。这一项修复消除了最主要的失败来源。

### 3.2 以可执行动作集为规范状态接口，建立实例级世界模型

原实现主要依赖对观察文本的正则解析，易出错，且在类型层面混同同类容器（如丢失 desk 1 与 desk 2 的编号）。新实现以环境返回的 `admissible_commands` 为主要状态来源（较文本正则更稳健），维护**带实例编号**的世界模型，并为每个容器维护单调推进的状态标志：visited → opened → searched → exhausted。反震荡因此改为"否决无状态进展的动作"，而非简单地抑制重复动作。

### 3.3 逐候选卦象评分架构

外围负责：从任务描述生成目标谓词、由可执行动作集构造候选动作集、并否决物理上不可能或已证明无进展的候选；卦象引擎则对每个存活候选构造六爻编码并打分，取 argmax 为最终动作。此设计使核心引擎实质参与每一步决策且其贡献可被消融量化（见第 6 节），同时否决逻辑只删候选、不指定胜者。

### 3.4 系统性消除五类失败模式

原实现的诚实成绩主要受限于五类系统性失败，逐一修复：

| 失败模式 | 修复方式 |
|---|---|
| 多位置之间无限往返 | 单调 searched 状态 + 否决无进展动作 |
| 闭合容器从不打开 | 将 open 从意图前置条件中解耦；处于闭合目标容器时 open 优先级最高 |
| 取—放原地死循环 | 记录物体来源实例，放置目标排除来源实例 |
| 检视类动作空转 | 默认否决 look / examine，卡死时触发前沿探索恢复而非空转 |
| 双物任务步数耗尽 | 取得第一件即送达，优先回访已知的第二件位置，并做剩余步数预算 |

### 3.5 语言目标解析与 train 聚合先验

将任务描述解析为结构化目标谓词（持有、清洁、加热、冷却、放置于、计数放置等），并引入从 train 划分统计得到的聚合先验（物体典型位置、过程—容器条件分布等）以指导探索顺序。先验为计数统计、仅取自 train 划分；其对留出集的零泄漏已在第 4.3 节独立验证。

> 上述改动共同将冻结泛化从约 40% 提升至 79.9%。**在此基础上**，对 valid 评测集失败做逐条错误分析并补充通用词典后可进一步达到转导上限（第 5 节）；但该增量属于针对特定评测集的调优，不计入泛化。

## 4. 未调参泛化结果（主结果）

### 4.1 valid_unseen 冻结首跑：79.9%

系统的开发全程仅使用 valid_seen 作为开发集，valid_unseen 在冻结代码后进行**首次**评测，结果为 **107 / 134 = 79.9%**。由于 unseen 在此之前从未被观察，该数字为严格的归纳泛化估计。

### 4.2 train 留出集：81.3%

为获得一个与 valid_unseen 完全独立、且从设计上排除任何泄漏的泛化估计，构造了如下留出实验：

**留出集构造。** 以固定随机种子（`seed = 20260723`）从 train 划分抽取 252 局，六种任务类型各 42 局；抽样按 game_file 路径排序后确定性采样，结果可复现（清单见 `heldout_games.json`）。这 252 局从未参与任何开发或调参，其失败模式从未被观察。

**先验隔离。** YLYW 使用一组从 train 统计得到的聚合先验。为避免先验"见过"留出集的标注，重建了一份**排除该 252 局**的先验（基于 train 其余 5134 局，`train_priors_heldout.json`），并以此运行留出评测。

**结果：205 / 252 = 81.3%。** 分任务类型：

| 任务类型 | 成功率 |
|---|---|
| pick_heat_then_place | 39 / 42 = 93% |
| pick_clean_then_place | 38 / 42 = 90% |
| look_at_obj_in_light | 38 / 42 = 90% |
| pick_and_place_simple | 31 / 42 = 74% |
| pick_cool_then_place | 30 / 42 = 71% |
| pick_two_obj_and_place | 29 / 42 = 69% |

### 4.3 先验零泄漏对照

为验证留出结果不依赖于先验对该子集标注的记忆，在同一留出集上追加了一次**完整先验**（含全部 5386 局）的对照评测：

| 先验版本 | 训练局数 | 成功率 | 逐局差异 |
|---|---|---|---|
| 排除 H（train \ H） | 5134 | 205 / 252 = 81.3% | — |
| 完整（含 H） | 5386 | 205 / 252 = 81.3% | **0 局翻转** |

两份先验确实不同（校验和不同，共 402 个统计字段存在差异），但在留出集上逐局胜负**完全一致**。这表明 train 先验的贡献来自真实的聚合规律（相关条件分布在移除 4.7% 的样本后比例保持稳定），而非对具体测试局标注的记忆——即**先验泄漏对留出结果的影响为零**。

### 4.4 一致性与失败同型

- **两估计一致**：冻结首跑 79.9% 与留出集 81.3% 相差仅 1.4 个百分点。两条完全独立的未调参路径给出高度一致的估计，表明约 80% 是该方法稳定的真实泛化水平。
- **失败同型**：留出集的 47 个失败经逐局核查，与 valid 集的失败**属同一类型**（目的地 / 物体名解析错误、空间指代误解析、多步时序任务、深藏实例在 50 步内探索超时、检视类任务无物体名线索），**未出现任何"仅在新数据上发生的新失败模式"**。这说明约 80% 反映的是方法在解析边界、探索预算与数据标注噪声上的固有上限，而非在新分布上的能力崩塌。

---

## 5. 转导口径上限（对照，非泛化）

在对 valid 两个划分的失败逐条做错误分析、并据此补充通用词典与修正解析规则后，系统可达如下上限：

| 评测集 | 成功率 |
|---|---|
| valid_unseen | 132 / 134 = 98.5% |
| valid_seen | 129 / 140 = 92.1% |

**该组数字为转导 / 开发集口径，不代表泛化。** 其与第 4 节泛化结果之间约 11–17 个百分点的差距，即为"针对特定评测集失败做词典与规则补充"所带来的过拟合增益。任何对外的泛化性陈述均应以第 4 节的归纳数字为准。

---

## 6. 组件消融

为界定各组件对性能的贡献，在两个划分上运行了四组消融（同一冻结代码，仅切换 L2 / L3 的启用方式）：

| 模式 | 含义 | valid_seen (140) | valid_unseen (134) |
|---|---|---|---|
| full | L2 六爻 × L3 卦象吉凶 | 129 = 92.1% | 132 = 98.5% |
| linear | 去除 L3 卦象层，仅用六爻线性幅度 | 128 = 91.4% | 132 = 98.5% |
| perm | 保留卦象匹配，随机置换 64 卦吉凶表 | 126 = 90.0% | 132 = 98.5% |
| fixed_yao | 冻结六爻为常量 [0.5]×6 | 41 = 29.3% | 37 = 27.6% |

**结论：**

1. **L2 六爻状态编码是主要承重组件。** 冻结六爻后成绩由 92.1% / 98.5% 崩塌至 29.3% / 27.6%，说明六维目标推进特征承载了绝大部分决策信号。需要注意的是，这六维特征本质上是一个通用的目标推进评分函数，`linear` 基线同样使用它；故该崩塌证明的是"目标特征工程有效"，而非某一特定符号系统的语义有效性。

2. **L3 卦象层对最终成功率贡献近于零。** 去除 L3（`linear`）后 valid_seen 仅少 1 局、valid_unseen 不变；full 与 linear 的 McNemar 配对检验 p = 1.0，与噪声不可区分。L3 每步仅在约 3.7%（unseen）/ 4.1%（seen）的多候选决策上改变 argmax，且几乎不改变任务成败。

3. **吉凶表的具体取值携带弱结构信息。** 随机置换吉凶表（`perm`）在 valid_seen 上比去除卦象（`linear`）还低 2 局，方向上表明"保持先验一致的排序优于随机排序"；但此为单次置换的观测，尚不足以支撑统计显著性结论。

综合而言，性能主要来自自然语言目标解析、train 聚合先验与否决 / 重试控制逻辑（本质为经典符号规划），L3 卦象层为"参与每步打分但近乎中性的排序因子"。

## 7. 文献定位

| 方法 | 是否用 LLM | valid_unseen | 口径 |
|---|---|---|---|
| BUTLER | 无（需模仿学习训练） | 37% | 归纳 |
| ExpeL | GPT-3.5 | 59% | 归纳 |
| ReAct | PaLM-540B | 71% | 归纳 |
| AutoGen | GPT-4 / 3.5 | 77% | 归纳 |
| EmbodiSkill | Qwen3.5-27B | 93.28% | 归纳（当前干净 SOTA） |
| Reflexion | GPT-3.5 | 97% | 转导（≤12 次自反思） |
| **本工作** | **无（CPU，~2 ms/步）** | **~80%（归纳）/ 98.5%（转导）** | 见第 4、5 节 |

在严格的归纳口径上，本方法（约 80%）低于当前干净 SOTA（EmbodiSkill 93.28%），高于 ReAct、ExpeL、BUTLER。在转导口径上，98.5% 的可比对象为 Reflexion（97%，同为多次重试的转导设置）。本方法的差异化优势在于完全不依赖大语言模型、可在 CPU 上实时运行、且结果完全确定可复现，其算力需求较上述基于 LLM 的方法低若干数量级。

## 8. 局限

1. **依赖环境终局信号的有界闭环重试。** 系统在放置未触发 `won` 时判定解析有误并回退换候选重试（硬上限 ≤10 次重试、≤50 步）。部分较难的胜局通过有界枚举撞中正确指代对象，而非一次性语言理解。该机制合法（仅依赖环境二值信号、不读取真值），但应理解为"针对环境终止信号的有界试错搜索"，而非零样本指令跟随；在无廉价终局信号或动作不可逆的场景中该机制将失效。
2. **领域特定的解析资源。** 系统使用约 58 条针对 ALFWorld 的词典条目与十余条控制护栏，覆盖边界为 train 中出现过的表述，迁移至其他环境需重写。
3. **目标粒度与基准判定。** ALFWorld 的成功检查多数只验证"某类物体位于某类容器"，忽略实例身份与空间限定词；因此部分成功反映了基准判定的宽松性，而非严格的空间指令跟随。
4. **参数量口径。** L3 卦象核心的 443 个参数在消融中近于惰性；对系统容量的诚实描述应为：443 卦象核心参数 + 约 50 个手工设定常数 + 约 58 条词典条目 + 若干消歧正则 + train 计数先验。
5. **剩余失败的性质。** 未解决的失败主要为：对抗性或错误标注的任务描述（数据问题）、无过程线索的过程任务（信息不在语言中，纯符号不可判）、深藏实例的探索超时（受 50 步预算限制）、以及少量复数计数与空间指代的解析错误。

## 9. 复现

**环境**：WSL2 Ubuntu-22.04 + Python 3.10 + alfworld 0.5.0（editable）+ textworld 1.7.0。

**命令**（工作目录 `ylyw/alfworld_exp/v18/`）：

```bash
# 未调参泛化 · valid_unseen 冻结首跑结果见 results_unseen_frozen_full.json（79.9%）
# 未调参泛化 · train 留出集（81.3%，先验零泄漏对照）
python run_v18_eval.py --split train --games-file heldout_games.json \
    --priors train_priors_heldout.json --output heldout_results_excl.json
python run_v18_eval.py --split train --games-file heldout_games.json \
    --priors train_priors.json          --output heldout_results_full.json
python _analyze_heldout.py

# 转导口径上限（对照）
python run_v18_eval.py --split valid_unseen --start 0 --end 134 --output results_unseen_v182.json
python run_v18_eval.py --split valid_seen   --start 0 --end 140 --output results_seen_v182.json

# 组件消融
bash run_ablations.sh          # linear / perm / fixed_yao × 两划分
```

**关键文件**：

| 文件 | 内容 |
|---|---|
| `results_unseen_frozen_full.json` | valid_unseen 冻结首跑（79.9%） |
| `heldout_games.json` | 留出集 252 局清单（seed=20260723） |
| `train_priors_heldout.json` | 排除留出集重建的先验 |
| `heldout_results_excl.json` / `heldout_results_full.json` | 留出评测（排除 H / 完整先验，均 81.3%） |
| `_ho_analysis.log` | 留出结果分析与失败归因 |
| `results_{seen,unseen}_v182.json` | 转导口径上限（92.1% / 98.5%） |
| `abl_{linear,perm,fixed_yao}_valid_{seen,unseen}_v182.json` | 消融四件套逐局结果 |
| `agent_v18.py`, `goal_parser.py`, `world_model.py`, `ylyw_scorer.py`, `run_v18_eval.py` | 决策与评测代码 |
| `build_train_priors.py`, `train_priors.json` | train 先验统计（n=5386） |

核心引擎 `ylyw/language/hanzi_engine.py` 与 `ylyw/ylyw_action_primitives.py` 在全部实验中未作修改。
