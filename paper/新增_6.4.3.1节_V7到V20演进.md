## 6.4.3.1 从V7到V20：汉字易理推理的技术演进

第6.4.3节报告的知几学习逐步引入实验（从V4随机基线到V10，成功率从3.7%攀升至92.5%）展示了YLYW在ALFWorld中的基本能力建立过程。但这一过程主要停留在**纯符号规则**层面——V7-V10的核心改进是知几学习（记忆成功/失败模式）和PDDL约束模板（动作顺序校验），并未触及底层语义理解的本质。

真正的范式转变发生在**汉字易理推理**的引入——这对应从V7纯符号规则到V20完整汉字易理推理的技术演进。表6.18a总结了关键版本的演化对比。

**表6.18a V7至V20关键技术演进对比**

| 版本 | 语义理解方式 | 决策机制 | 动作空间 | 成功率（valid_unseen） | 核心限制 |
|:--|:--|:--|:--|:--:|:--|
| V7 | 纯字符匹配（硬编码词表） | 刚性状态机 | 6个+look | ~64% | 无法处理未知实体 |
| V13 | 中文转英文+正则解析 | 规则+PDDL | 12个+look | ~73% | 翻译丢失语义 |
| V17 | 汉字部首→八卦隶属度 | 六爻评分+扩展动作库 | 30个+look | ~87% | 动作库过强依赖 |
| V18 | 汉字部首→八卦隶属度 | YLYW六爻评分器 | 12个精选 | 98.5%（132/134） | 纯符号状态追踪 |
| V20 | 完整汉字语义引擎 | YLYW六爻评分+CnWorldModel | 12个精选 | **98.5%**（132/134；含概率采样） | 极少数语言歧义 |

### V7：纯符号规则阶段（2026.06.27）

V7是YLYW ALFWorld agent的第一个可用版本。其语义理解完全基于**硬编码的中文词表匹配**：系统将环境返回的英文文本通过静态对照表逐词翻译为中文（如"counter"→"柜台"），然后在硬编码的规则链中查找对应的动作模板。

决策机制是一个**刚性状态机**（FSM），包含约6个硬编码子目标序列：

```
子目标1: 找物体 → 在admissible commands中查找"找/看/搜索 + [物体名]"
子目标2: 拿物体 → 查找"拿/取/捡 + [物体名]"
子目标3: 操作物体 → 查找"用/打开/加热 + [物体名]"
子目标4: 放置物体 → 查找"放/搁/置 + [位置]"
```

评分方式为简单的**加法评分**：对每个候选动作计算与目标词的重叠字数，重叠越多得分越高。例如，如果目标是"拿苹果"，候选动作中"拿苹果"重叠2字得2分，"拿香蕉"重叠1字得1分。

**致命缺陷**：无法处理未知实体。如果环境中出现一个从未见过的物体（如"peach"→"桃子"在词表中不存在），系统不知道如何与之交互——它会跳过该物体或选择一个完全无关的动作，导致任务失败。

V7在valid_unseen上的成功率为~64%。

### V13：中文翻译+正则解析阶段（2026.07.01）

V13尝试通过**中文→英文翻译**来绕过语义理解瓶颈：将环境的中文文本转译为英文，然后通过英文正则表达式解析出实体名和状态。这利用了ALFWorld原始环境的英文接口优势。

决策机制升级为**规则+PDDL约束**的双层架构：上层PDDL规则校验动作序列的合法性（"加热前必须先取出"），下层执行具体的动作匹配。

动作空间扩充至12个动作+look，覆盖了ALFWorld中大部分标准操作。

然而，翻译过程本身引入了**语义丢失**——中文到英文的直译丢掉了"柜橱"和"柜子"的语义关系、"热"和"暖"的温度共通性等细微信息。V13在valid_unseen上的成功率为~73%。

### V17：部首→八卦感知阶段（2026.07.14）

V17是汉字YLYW推理的第一个里程碑。核心突破是：**不再依赖英文翻译，直接用汉字部首的八卦隶属度来做感知**。系统通过第2.6节描述的汉字引擎将每个实体名映射为8维八卦向量，在八卦语义空间中执行匹配，而非在字符串空间中执行精确匹配。

这一阶段引入了**六爻评分器**的基本架构——12种基础策略类型（pick、go_to、put、heat、clean、cool、look_at、find、discard、examine、use、open_container）各自对应一个6维模板向量。决策时，计算当前状态六爻与每个策略模板的匹配得分，选择得分最高的策略。这与第3章物理抓取的评分范式一致（该范式后经"方案A"升级为加权汉明+连续值细化的两级匹配）。

动作空间扩充至30个动作+look，覆盖了大量场景特化动。"动作库过强"也是一个问题——太多的特化动作导致选择空间过大，且不同动作间的决策边界模糊。

V17在valid_unseen上的成功率达到~87%。

### V18：YLYW六爻评分器成熟版（2026.07.17）

V18是V17的精化版本。核心改进有三：

1. **动作空间回归精选**：从30个特化动作回归到12个核心动作，每个动作经过六爻评分独立验证，确保决策边界清晰。
2. **score_action()评分公式优化**：从简单的相似度排序扩展为五因素的加权综合评分——卦象匹配得分、成功历史、目标匹配度、动作可行性、效率偏好。
3. **亥爻概率采样**：在评分相等或相近的情况下，引入基于成功历史的概率采样来选动作，增加策略的柔性。

V18在valid_unseen 134局上达到98.5%（132/134，仅失败2局）。代码量约1500行Python。

### V20：完整汉字易理推理+世界模型（2026.07.25）

V20是当前ALFWorld agent的最高版本，代表从"规则驱动的符号系统"到"易理驱动的感知-决策统一框架"的完整转变。核心设计如下：

**汉字世界模型（CnWorldModel）**。V20用一个基于YLYW的汉字世界模型替代了V18中的纯符号状态追踪器。所有环境状态都用汉字表示，通过YLYW三层感知（字→词→句）来理解。对比V18的Python dataclass状态维护，V20的CnWorldModel直接将环境文本输入汉字引擎，输出卦象编码的状态表征——不需要人工设计的正则表达式和状态字段。

**卦象知识库（GuaKnowledgeBase）**。V20维护一个基于《说卦传》万物类象的实体→八卦映射知识库，约150个ALFWorld实体。每个实体的向量由手工先验定义（如"苹果"→艮0.85），并支持运行时学习——随着交互次数增加，卦象隶属度会根据成功/失败历史自动微调。

**V18→V20的继承与改进**：

| 组件 | V18 | V20 |
|:--|:--|:--|
| 语义感知 | 正则解析英文→查表翻译中文 | 汉字引擎直接感知（字→词→句YLYW） |
| 状态追踪 | Python dataclass（人工定义字段） | CnWorldModel（YLYW卦象编码） |
| 实体知识 | 有限的静态词表 | GuaKnowledgeBase（万物类象知识库） |
| 决策评分 | score_action()五因素评分 | YLYW六爻评分器（同V18但更精确） |
| 动作空间 | 12个动作 | 12个动作（精选） |
| 学习机制 | 知几学习（V18已有） | 知几学习+卦象频率学习 |

**实验表现**：V20在valid_unseen 134局上达到**98.5%**（132/134，仅失败2局），valid_seen 140局92.1%（129/140），两组合计95.3%（261/274）。注意口径：**98.5%是valid_unseen的单集成绩，95.3%是274局的合计成绩**，二者不可混用。V18在同一批valid_unseen上同为132/134，故V20的增量主要体现在未知实体的语义泛化能力，而非该基准的绝对成功率。另需如实说明：将卦象知识库冻结后，同一批次降至79.9%（107/134），即该成绩部分来自运行时的在线知识积累（详见6.4节的分布依赖消融）。

### 范式转换的本质

从V7到V20的演进，本质上是从**"手写规则匹配"到"六爻评分器"的范式转换**：

- **V7范式**：if 目标 == "加热食物" and 持有 == "食物" then 执行"微波炉加热"。规则是离散的、刚性的——遇到边界条件就失效。
- **V20范式**：当前状态的六爻向量与12个策略模板做"方案A"两级匹配（加权汉明粗选+连续值细化）并排序，选得分最高的执行。评分是柔性的——任何状态都有一个"最接近"的策略，不存在未覆盖的状态。

**汉字部首推理的泛化能力**是这一转换的关键支撑：V7通过字符串精确匹配知道"苹果"是苹果，但它不知道"桃子"也是水果（艮卦族，与苹果同类）。V20通过八卦隶属度知道"桃子"的卦象谱系与"苹果"高度相似（艮0.80 + 兑0.30 + 坤0.25），因此可以自动将对苹果的处理经验迁移到桃子上。这正是第1章所论述的结构化先验的泛化优势——不是从数据中统计泛化，而是从符号空间中的语义近似泛化。

**V7与V20对比概览**：

| 维度 | V7 | V20 |
|:--|:--|:--|
| 语义理解 | 精确字符串匹配 | 八卦隶属度近似匹配 |
| 决策机制 | 刚性状态机（6子目标） | 六爻评分器（12策略模板） |
| 实体泛化 | 无——未知实体不可处理 | 有——通过卦象谱系近似泛化 |
| 汉字推理 | 无 | 部首→八卦→六爻→64卦 |
| 成功率(valid_unseen) | ~64% | **98.5%（132/134）** |
| 参数量 | ~500行硬编码规则 | ~1500行Python + 443参数YLYW核心 |
| 推理时间/局 | ~0.5秒 | ~1.3秒（含环境I/O） |
